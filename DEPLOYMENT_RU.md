# 🎞️ Киноплёнка — инструкция по развёртыванию (GitHub + Cloudflare)

Эта инструкция написана для человека без большого опыта программирования.
Всё можно сделать через браузер (в том числе с телефона), кроме одного шага
с базой данных, где удобнее один раз воспользоваться компьютером
(объяснено ниже — раздел 5).

Схема работы бота:

```
GitHub (код) → Cloudflare Workers (запускает код) → Telegram Webhook → Telegram Bot API
                        ↑
                 Cloudflare D1 (база данных фильмов)
```

---

## 1. Создание аккаунта GitHub и репозитория

1. Откройте https://github.com и нажмите **Sign up**, если аккаунта ещё нет.
   Укажите email, придумайте пароль и логин, подтвердите почту.
2. После входа нажмите **+** в правом верхнем углу → **New repository**.
3. Укажите:
   - **Repository name**: например `kinoplyonka-bot`.
   - Видимость: **Private** (рекомендуется, так как внутри могут быть
     служебные файлы конфигурации) или Public — на ваше усмотрение.
   - Остальные galochki (README, .gitignore, license) можно оставить
     пустыми — они уже есть в проекте.
4. Нажмите **Create repository**.

---

## 2. Какие файлы нужно загрузить

Загрузите **весь проект целиком**, сохраняя структуру папок:

- `src/` (вся папка со всеми вложенными файлами);
- `scripts/` (необязательно, но можно оставить);
- `schema.sql`;
- `wrangler.toml`;
- `package.json`;
- `.gitignore`;
- `README.md`, `DEPLOYMENT_RU.md`.

**Не загружайте** файл `.dev.vars` (если вы его создавали локально) — там
может быть настоящий токен бота. Он и так исключён через `.gitignore`.

## 3. Как загрузить проект на GitHub (с телефона или компьютера)

Самый простой способ — через веб-интерфейс GitHub:

1. Откройте созданный репозиторий на github.com.
2. Нажмите **Add file → Upload files**.
3. Перетащите файлы/папки (либо выберите их через проводник телефона —
   большинство мобильных браузеров позволяют загружать целые папки как
   zip; если ваш браузер не даёт загрузить папку, загрузите файлы по
   одной папке за раз, GitHub сам создаст нужные подпапки, если в пути
   файла есть `/`).
4. Внизу страницы нажмите **Commit changes**.

Если вам удобнее с компьютера — можно также использовать Git:

```bash
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/kinoplyonka-bot.git
git push -u origin main
```

## 4. Подготовка данных, которые понадобятся дальше

Прежде чем идти в Cloudflare, соберите четыре вещи:

1. **Токен бота (BOT_TOKEN)**
   - Откройте Telegram, найдите бота **@BotFather**.
   - Отправьте `/newbot` (или используйте существующего бота).
   - Укажите имя и username бота.
   - BotFather пришлёт токен вида `123456789:AA...` — сохраните его.

2. **ID/username канала (CHANNEL_ID) и ссылка на канал (CHANNEL_URL)**
   - Если канал публичный: `CHANNEL_ID` = `@имя_канала`,
     `CHANNEL_URL` = `https://t.me/имя_канала`.
   - Если канал приватный: узнайте числовой ID (например, через бота
     @userinfobot, переслав ему сообщение из канала, либо через
     @RawDataBot). ID приватного канала выглядит как `-100xxxxxxxxxx`.
     `CHANNEL_URL` в этом случае — это пригласительная ссылка канала
     (Приглашение → Создать ссылку-приглашение).
   - **Важно:** бот должен быть добавлен в канал **администратором** —
     иначе он не сможет проверять подписки.

3. **Telegram ID администратора(ов) (ADMIN_IDS)**
   - Напишите боту **@userinfobot** — он пришлёт ваш числовой ID.
   - Если администраторов несколько, перечислите ID через запятую:
     `111111111,222222222`.

4. **Секрет для вебхука (WEBHOOK_SECRET)**
   - Просто придумайте длинную случайную строку (например, набор из
     30+ случайных букв и цифр). Она нужна, чтобы никто посторонний не
     мог присылать боту поддельные сообщения.

## 5. Создание базы данных Cloudflare D1

1. Зайдите на https://dash.cloudflare.com и войдите/зарегистрируйтесь.
2. В левом меню выберите **Workers & Pages** (не бойтесь пункта Pages,
   он там же).
3. Найдите раздел **D1** (иногда находится как отдельный пункт **D1 SQL
   Database** в левом меню, либо внутри Workers & Pages → Storage).
4. Нажмите **Create database**.
5. Назовите базу `kinoplyonka-db` и создайте.
6. Откройте созданную базу — скопируйте её **Database ID** (понадобится
   на следующем шаге).
7. Внутри базы найдите вкладку **Console** (консоль запросов).
8. Откройте файл `schema.sql` из проекта, скопируйте его содержимое
   целиком и вставьте в консоль, затем выполните (Execute/Run). Это
   создаст таблицы `movies`, `users`, `sessions`, `message_context`.

   > Если вы работаете с компьютера и вам удобнее через терминал, можно
   > вместо этого один раз установить Node.js, выполнить `npm install`,
   > а затем `npm run db:init:remote` — команда сама применит `schema.sql`
   > к настоящей (продакшн) базе через Wrangler CLI.

9. Откройте файл `wrangler.toml` в вашем репозитории на GitHub, нажмите
   иконку карандаша (Edit), найдите строку:

   ```
   database_id = "PASTE_YOUR_DATABASE_ID_HERE"
   ```

   и замените `PASTE_YOUR_DATABASE_ID_HERE` на скопированный Database ID.
   Сохраните изменения (Commit changes).

## 6. Создание Worker'а в Cloudflare и подключение GitHub

1. В Cloudflare Dashboard откройте **Workers & Pages** → **Create**.
2. Выберите **Import a repository** (иногда называется **Connect to
   Git**).
3. Авторизуйте доступ Cloudflare к вашему GitHub-аккаунту, если это
   запрашивается впервые.
4. Выберите репозиторий `kinoplyonka-bot`.
5. На экране настройки сборки:
   - **Build command**: оставьте пустым (проект не требует сборки).
   - **Deploy command**: `npx wrangler deploy` (обычно определяется
     автоматически по наличию `wrangler.toml`).
   - Framework preset: можно оставить "None"/"Workers".
6. Нажмите **Save and Deploy**. Cloudflare выполнит первый деплой (пока
   без секретов бот ещё не будет работать — это нормально, секреты
   добавим на следующем шаге).

После этого у Worker'а появится адрес вида:

```
https://kinoplyonka-bot.ВАШ_АККАУНТ.workers.dev
```

Сохраните этот адрес — он понадобится для настройки Webhook.

## 7. Добавление переменных окружения и секретов

1. Откройте созданный Worker в Cloudflare Dashboard.
2. Перейдите во вкладку **Settings → Variables and Secrets**
   (в интерфейсе Cloudflare раздел может называться **Environment
   Variables**).
3. Добавьте по одному значению как **Secret** (это важно — не как
   обычную переменную, чтобы значения не показывались открытым текстом):

   | Имя переменной   | Значение |
   |------------------|----------|
   | `BOT_TOKEN`      | токен от BotFather |
   | `CHANNEL_ID`     | `@имя_канала` или `-100...` |
   | `CHANNEL_URL`    | `https://t.me/...` |
   | `ADMIN_IDS`      | `111111111,222222222` |
   | `WEBHOOK_SECRET` | ваша случайная строка |

4. Сохраните — после сохранения секретов Cloudflare обычно предлагает
   передеплоить Worker; согласитесь (Deploy/Redeploy).

5. Проверьте привязку базы данных D1: **Settings → Bindings** (или
   **Functions → D1 database bindings**) — должна быть привязка с
   именем `DB`, указывающая на `kinoplyonka-db`. Если вы создавали
   проект через **Import a repository**, Cloudflare обычно берёт эту
   привязку прямо из `wrangler.toml` автоматически (поскольку там уже
   указан `database_id`). Если привязки нет — добавьте её вручную:
   **Add binding → D1 database**, имя переменной `DB`, база
   `kinoplyonka-db`.

## 8. Настройка Telegram Webhook

Это последний шаг, после которого Telegram начнёт присылать сообщения
пользователей на ваш Worker.

Самый простой способ — открыть специальную ссылку в браузере телефона
(замените `<TOKEN>`, `<WORKER_URL>` и `<SECRET>` на свои значения):

```
https://api.telegram.org/bot<TOKEN>/setWebhook?url=<WORKER_URL>&secret_token=<SECRET>
```

Пример:

```
https://api.telegram.org/bot123456:AAExample/setWebhook?url=https://kinoplyonka-bot.myaccount.workers.dev&secret_token=my-long-random-string
```

Если в ответ пришло `{"ok":true,"result":true,...}` — вебхук настроен
успешно.

Проверить текущее состояние вебхука можно так же через браузер:

```
https://api.telegram.org/bot<TOKEN>/getWebhookInfo
```

> Альтернатива для тех, кто работает с компьютера: скрипты
> `scripts/set-webhook.js`, `scripts/webhook-info.js`,
> `scripts/delete-webhook.js` делают то же самое из терминала
> (`BOT_TOKEN=... WORKER_URL=... WEBHOOK_SECRET=... node scripts/set-webhook.js`).

## 9. Проверка, что всё работает

1. Откройте вашего бота в Telegram и отправьте `/start`.
2. Должно прийти приветственное сообщение с кнопкой **➡️ Дальше**.
3. Нажмите «Дальше» → появится запрос на подписку с кнопками
   **📢 Подписаться на канал** и **✅ Проверить подписку**.
4. Подпишитесь на канал → нажмите «Проверить подписку» → должно прийти
   подтверждение и открыться главное меню (клавиатура снизу экрана).

- [ ] «📜 Инструкция» — показывает инструкцию с кнопкой «Назад».

- [ ] `/addmovie` — проходит по всем шагам (название → страна → год →
      рейтинг → описание → постер → код → сервисы → подтверждение).
- [ ] `/addservice` — досрочно завершает добавление сервисов.
- [ ] Сохранение/отмена (`💾 Сохранить` / `❌ Не сохранять`) работают

- [ ] `/editmovie` — позволяет выбрать фильм и изменить любое поле, затем

- [ ] `/deletemovie` — запрашивает подтверждение и удаляет фильм; фильм

- [ ] `/cancel` — отменяет текущую операцию добавления/редактирования.
- [ ] Обычный пользователь не видит и не может использовать админ-команды.

## 11. Просмотр логов в Cloudflare

1. Откройте Worker в Cloudflare Dashboard.
2. Перейдите во вкладку **Logs** (может называться **Real-time Logs** /
   **Tail**).
3. Нажмите **Begin log stream** (или аналогичную кнопку) — вы увидите
   вывод `console.log`/`console.error` из кода в реальном времени, пока
   отправляете боту команды в Telegram.

## 12. Частые проблемы и их решение

**Бот не отвечает вообще**
- Проверьте `getWebhookInfo` (см. раздел 8) — поле `url` должно
  совпадать с адресом вашего Worker'а, а `last_error_message` должно
  быть пустым.
- Убедитесь, что все 5 секретов добавлены и Worker передеплоен после
  их добавления.

**Ошибка при проверке подписки / бот всегда говорит "не подписан"**
- Убедитесь, что бот добавлен в канал именно как **администратор**.
- Проверьте, что `CHANNEL_ID` указан верно (с `@` для публичных каналов
  или в формате `-100...` для приватных).

**Не приходит постер / ошибка при отправке карточки**
- Убедитесь, что при добавлении фильма вы отправили именно **фото**
  (не файл-документ) на шаге "Отправьте постер".

**Ошибка "database_id" / D1 not found**
- Проверьте, что в `wrangler.toml` указан правильный `database_id`, и
  что привязка `DB` действительно настроена в **Settings → Bindings**
  Worker'а.

**Код фильма не находится**
- Поиск по коду не чувствителен к регистру, но чувствителен к лишним
  пробелам — проверьте, что код введён без опечаток.

**Изменения не появляются на боте после правок в GitHub**
- Убедитесь, что Cloudflare действительно запустил новый деплой после
  вашего коммита (вкладка **Deployments** Worker'а). Если проект
  подключён через Git-интеграцию, деплой запускается автоматически при
  каждом push в основную ветку (`main`).

## 13. Как обновить бота позже

1. Внесите изменения в файлы прямо на GitHub (карандаш → правка →
   Commit changes) или через `git push`, если работаете с компьютера.
2. Если Worker подключён через Git-интеграцию (раздел 6) — Cloudflare
   автоматически пересоберёт и передеплоит Worker при каждом коммите в
   ветку `main`. Прогресс можно увидеть во вкладке **Deployments**.
3. Если вы меняли `schema.sql` (структуру базы данных) — новые SQL-
   команды нужно выполнить вручную через консоль D1 (раздел 5, шаг 8),
   так как деплой Worker'а сам по себе не изменяет уже существующие
   таблицы.

## Важное примечание о тестировании

Поведение внутри самого Telegram (доставка сообщений, работа кнопок,
поведение вебхука на реальных серверах Cloudflare) было проверено
только на уровне логики кода и структуры проекта — оно не может быть
по-настоящему протестировано без реального развёртывания в Cloudflare и
реального Telegram-бота. После выполнения шагов выше обязательно
пройдите чек-лист из раздела 10 на живом боте.
